## 产品概述
最后一个 planned 占位页「模型微调 /models/finetune」落成真实页面。平台当前没有任何真实微调训练后端（LLM 供应商仅接入 OpenAI 兼容的对话/向量/重排调用，无 fine-tune 接口），因此页面落地为「微调准备中心」：为真正发起供应商侧微调训练做数据准备与校验，并对无法兑现的训练执行环节如实标注，不伪造任务 UI。

## 核心功能
- 训练数据格式校验器（真实可用）：支持粘贴或上传 JSONL/多行 JSON，识别 OpenAI Chat（messages）与 prompt/completion 两种格式，逐行校验 JSON 可解析性、必填字段、role 取值、content 非空、角色顺序建议、空内容等问题，输出统计卡（行数/有效/问题/字符与 token 粗估/样本类型）与可定位的问题行列表，并提供合规示例数据一键填充
- 微调流程时间线指引：准备数据→格式校验→发起训练（如实标注"训练服务接入中"）→效果评估与发布（标注后续规划）
- 供应商微调能力说明表：静态真实信息展示阿里云百炼、火山方舟、DeepSeek、Moonshot 等 OpenAI 兼容体系对微调的支持情况与官方入口链接（稳定根地址 + "以官方页面为准"提示），注明平台内暂未接入对应训练 API
- 页面顶部/底部给出诚实边界说明：训练执行与计费在供应商侧完成，平台当前提供的是数据准备与格式校验能力

## 技术选型
- 纯前端实现，零后端改动（库中不存在任何 fine-tune 表/接口，不臆造调用）
- 沿用项目既有栈：Vue 3 + TypeScript + Element Plus + Vite；样式复用全局 CSS 变量令牌（--bg-card/--border-color/--bg-fill/--text-secondary/--text-tertiary/--color-primary 等，支持暗色切换）

## 实现方案
### 目标文件
- 新建：frontend/src/views/models/finetune/index.vue（本仓库无此目录，需新建）
- 修改：frontend/src/router/index.ts、frontend/src/config/menu.ts、frontend/src/views/support/changelog/index.vue
- 模板骨架与统计卡样式参照已完成的 frontend/src/views/models/playground/index.vue；文件读取参照 frontend/src/views/knowledge/index.vue（FileReader.readAsText，单文件上限 5MB，超出提示改用手动粘贴）

### 校验引擎设计（页面内纯函数，不做成独立文件以免过度拆分）
- 按行切分后逐行 JSON.parse（一次遍历 O(n)，避免整文件解析），每行产出 {lineNo, ok, type(messages|prompt-completion|unknown), errors[]}
- 格式判定：含 messages 数组→Chat 格式；含 prompt 且含 completion→补全格式；两者都有或都没有→报错并给出修正建议
- Chat 格式规则：messages 为非空数组；每条含 role 且取值 ∈ system/user/assistant/tool；content 为字符串且非空；可选顺序提示（system 放首、user/assistant 交替）；tool 消息应带 tool_call_id 提示（仅提示不判错）
- 补全格式规则：prompt/completion 均为非空字符串
- token 粗估（注明仅供参考）：ASCII 字符数 /4 + 非 ASCII 字符数 *1，四舍五入到整数
- 示例数据：内置一组 3-5 行合规 Chat 格式样例（贴近客服问答场景）供一键填充，空状态引导先看示例

### 页面结构（单内容页，模块化分块）
1. 页面头部：标题/描述 + 右侧「加载示例」「清空」按钮
2. 微调流程时间线：el-steps 四步，第 3/4 步用说明文案标注"训练服务接入中/规划中"，不渲染假进度
3. 数据校验工作台：格式选择（自动识别为主，可手动指定）→ 文本输入（textarea 粘贴）与文件上传（el-upload 自实现 + FileReader）双入口 → 校验按钮
4. 统计卡：总行数/有效行/问题行/预估 token/对话样本数（真实计算结果）
5. 问题列表：el-table 展示问题行号、原始内容截断、错误原因，支持点击跳转定位到 textarea 行（textarea 支持 gotoLine 由行号换算 scrollTop 或提示行号）
6. 供应商微调能力说明表：el-table 静态常量数组渲染（供应商/微调格式/支持状态/说明/官方入口链接，链接新窗口打开、根地址 + 以官方页面为准）
7. 边界说明条：训练执行与计费在供应商侧完成，平台内暂未接入训练任务管理，当前提供数据准备与校验

## 设计风格
作为平台「模型」分组内的内容页，延续现有控制台风格：浅色为主、支持暗色切换。整页采用工具工作台式布局——上部流程时间线与数据录入区，中部统计与问题列表，下部供应商能力参考表，视觉上通过圆角卡片、柔和边框与 hover 上浮营造节奏感；校验结果用明确的成功/告警/错误色块区分，让"准备数据→发现问题→修正"的操作路径一目了然。所有色彩与间距引用全局 CSS 变量，保证与已完成页面（模型广场等）风格一致。

## 页面规划（单内容页分块）
- 块 1 页面头部：标题「模型微调」+ 说明文字（平台内完成数据准备与校验，训练在供应商侧执行），右侧「加载示例」主按钮
- 块 2 流程时间线：横向四步（准备数据/格式校验/发起训练/评估发布），第 3 步以虚线/标签标注"服务接入中"，第 4 步标注"规划中"
- 块 3 数据录入工作台：双入口卡片（粘贴 JSONL 文本 / 上传 .jsonl 或 .txt 文件，≤5MB），支持手动指定格式，含"加载合规示例"快捷动作
- 块 4 统计卡行：总行数/有效行/问题行/预估 token/对话样本数五个指标卡，问题行 >0 时数字呈告警色
- 块 5 校验结果：无问题时成功状态空态提示；有问题时 el-table 列出问题行（行号/片段/原因），行号可点击并定位
- 块 6 供应商能力说明表：四列表格（供应商/微调格式/支持状态/说明与官方入口），状态列用标签区分"支持/以官方为准"
- 块 7 边界提示条：说明训练执行与计费在供应商侧完成，平台当前提供数据准备与校验能力
