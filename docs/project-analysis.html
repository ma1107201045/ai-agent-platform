01一句话结论

这是一个架构设计合格、功能骨架完整、但尚未做好生产准备的中期项目。后端分层清晰、工作流引擎设计相当成熟（DAG 并行调度、环检测、节点级容错一应俱全），知识库 RAG 是真实可用的全链路实现而非演示桩。主要短板集中在三处：安全体系基本空白（MVEL 无沙箱 + 免鉴权接口 = 匿名远程代码执行）、零测试覆盖、以及前端单文件过度膨胀。当前状态适合作为内部 PoC 继续演进，不建议直接对外部署。

05架构亮点

  • 工作流引擎设计水准超出一般项目。引擎只管调度（依赖解析、并行控制、分支释放、执行策略、轨迹归集），节点语义全部下沉到 NodeHandler，靠 Spring 自动注册。排他分支用 selectedHandle 精确释放、未选中分支整链标记 skipped，join 节点靠 normalHits 判断是否至少有一个上游正常完成——这套语义相当严谨。
  • 依赖方向单向且干净。web → service → workflow/dao/llm → common，agent-workflow 通过 spi 包（AgentRunner / ModelProvider / KnowledgeProvider）反向依赖业务实现，避免了引擎直接耦合 service 层。
  • 知识库是真做，不是演示。PDFBox 解析 PDF、POI 解析 docx（段落+表格）、UTF-8 失败回退 GBK、分批 16 条向量化、真实余弦相似度——整条链路都落地了。
  • 前端类型质量好。tsconfig 开 strict + noUnusedLocals/Parameters，vue-tsc --noEmit 零错误；主题三态（light/dark/auto）含系统偏好监听；画布支持撤销重做这类高成本交互。
  • SQL 脚本幂等且注释完整。13 张表全部带中文注释，脚本可重复执行、自动补齐缺失列。

07改进建议（按优先级）

第一阶段 · 安全止血（1 周内）

  • 给 MVEL 上锁：引入类白名单 + 自定义 ClassLoader 隔离 + 单表达式超时中断；或直接把 code 类型工具替换为受限的表达式求值（如 Aviator、SpringEL with SimpleEvaluationContext）。
  • 收紧公开接口：/api/portal/** 增加应用级发布状态校验 + 限流，禁止匿名用户触发任意工具执行。
  • 密钥外置：JWT secret 与 DB 密码改走环境变量，轮换已泄露的密钥，并把 application.yml 加入 .gitignore 模板化。
  • 补归属校验：在 Service 层统一封装「按 id 查询并校验 userId/tenantId」的受保护查询方法，替换四处直查。
  • 最小权限模型：sys_user 增 role 字段，Controller 增加管理员校验，模型 apiKey 返回时脱敏。

第二阶段 · 补齐基本盘（2-4 周）

  • 补测试：优先覆盖 WorkflowEngine（环检测、并行 join、分支跳过、错误传播）、AgentRunner 的工具调用循环、知识库分块与检索——这三处是系统核心且最易回归。
  • 引入向量检索：数据量达到千级分块前切换到 Milvus / pgvector，或至少加一层内存缓存避免每次全量反序列化。
  • workflow 模式流式化：让引擎支持节点完成事件推送（SSE），前端逐节点渲染轨迹，彻底解决长流程白屏。
  • HTTP 出站管控：加协议白名单（仅 https）、内网段黑名单、禁止跟随重定向。
  • 模型连通性测试：供应商保存前发起一次轻量调用验证。

第三阶段 · 结构与体验（1-2 月）

  • 拆分 edit.vue：抽出 useFlowCanvas / useFlowHistory / useFlowDebug 三个 composable，配置面板按节点类型拆分子组件。
  • Markdown 换成熟库：marked / markdown-it + DOMPurify，公开对话页同步接入。
  • 收敛占位菜单：把 32 个占位项改为「敬请期待」禁用态或直接从菜单移除。
  • 扩展 LLM SPI：按需补充 Anthropic / 国产模型 Provider，工厂加缓存复用 HttpClient。
